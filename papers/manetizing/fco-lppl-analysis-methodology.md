# FCO LPPLSモデル解析手法の詳細分析
**ETH Zurich Financial Crisis Observatory (FCO)の手法調査結果**

## 1. LPPLS (Log-Periodic Power Law Singularity) モデルの詳細

### 1.1 理論的基礎
LPPLSモデルは金融バブルの「指紋」を検出するために設計され、以下の前提に基づく：
1. **超指数的成長**: バブル期には価格が指数関数より速く上昇（下落）
2. **対数周期振動**: バブル終盤に向けてボラティリティが加速
3. **有限時間特異点**: 臨界時間tcでバブルが崩壊

### 1.2 数学的定式化
```
E[ln(P(t))] = A + B(tc - t)^m + (tc - t)^m [C1 cos(ω ln(tc - t)) + C2 sin(ω ln(tc - t))]
```

**7つのモデルパラメータ：**
| パラメータ | 意味 | 役割 |
|----------|------|------|
| A | 有限ピーク/谷の対数価格 | バブル終了時の価格水準 |
| B | べき乗強度 | トレンドの強さ |
| m | べき乗指数 | 価格加速度（通常0.1-0.9） |
| C1, C2 | 振動振幅係数 | 対数周期振動の大きさ |
| ω | 角周波数 | 振動の頻度 |
| tc | 臨界時間 | バブル崩壊予測時刻 |

### 1.3 フィッティング手法
- **Ordinary Least Squares (OLS)** と **非線形最適化** の組み合わせ
- 過剰適合を避けるため、複数の時間窓で逐次的にフィッティング

## 2. 多重時間窓分析プロセス

### 2.1 分析手順
1. **固定終了時刻 (t2)** を設定（通常は分析日）
2. **複数の開始時刻 (t1,i)** を選択
3. 各時間窓 [t1,i, t2] でLPPLSモデルをフィッティング
4. パラメータセットのコレクションを取得

### 2.2 時間スケールの分類
- **Super Short**: 100-200日（極短期分析）
- **Short Term**: 150-300日（短期分析）
- **Long Term**: 500-1500日（長期分析）

## 3. 信頼性評価システム

### 3.1 DS LPPLS Confidence Indicator
- **定義**: 異なるサイズの時間窓で検出された超指数的価格動向の存在を定量化
- **高い値の意味**: 多くの時間スケールでLPPLSシグネチャーが検出
- **閾値の目安**:
  - 0-10%: バブル兆候なし
  - 10-30%: 弱いバブル兆候
  - 30-50%: 中程度のバブル
  - 50%以上: 強いバブル兆候

### 3.2 DS LPPLS Trust Indicator
- **手法**: ブートストラップ法による統計的信頼性評価
- **目的**: Confidence指標の堅牢性を測定
- **解釈**: Trust指標が高いほど、検出されたバブルシグナルの信頼性が高い

### 3.3 クラスター分析
**k-meansクラスタリング手法：**
1. 異なる時間窓から得られたフィットパラメータセットをクラスタリング
2. 最大クラスターの統計量を算出：
   - **平均臨界時間 (μtc)**: クラッシュ予測の中心値
   - **標準偏差 (σtc)**: 予測の不確実性
   - **シナリオ確率**: 最大クラスター内のフィット数 ÷ 全フィット数

## 4. レポート構成と提供指標

### 4.1 分析対象規模
| カテゴリ | 資産数 | 内容 |
|---------|--------|------|

### 4.2 個別資産の分析結果テーブル

**Bubble Dataセクション：**
| 指標 | 単位 | 説明 |
|------|------|------|
| Bubble Size (bs) | % | バブルの規模（価格変動幅） |
| Bubble CAGR (bg) | % | 年間複合成長率 |
| Duration | days | バブル継続期間 |
| Bubble Progress (bp) | % | バブルの進行度（0-100%） |
| Geometric Average | % | √(bs × ci) によるランキング指標 |

**Cluster Analysisセクション：**
| 指標 | 単位 | 説明 |
|------|------|------|
| Critical Time Prediction | 日付 | クラッシュ予測日（μtc） |
| σtc | days | 予測の標準偏差（不確実性） |
| Scenario Probability | % | 最も可能性の高いシナリオの確率 |

### 4.3 視覚化要素
- **青線**: 累積リターン（左軸、%）
- **緑色領域**: 正のバブル指標（DS LPPLS Confidence）
- **赤色領域**: 負のバブル指標
- **色付き背景**: 現在のバブル期間（開始から現在まで）

### 5.2 個別株式の4象限分析
Value Score（ファンダメンタルズ）とGrowth Score（価格動向）の2軸で分類：
- **Quadrant 1**: 強い正のバブル + 強いファンダメンタルズ
- **Quadrant 2**: 強い正のバブル + 弱いファンダメンタルズ（最も危険）
- **Quadrant 3**: 強い負のバブル + 弱いファンダメンタルズ
- **Quadrant 4**: 強い負のバブル + 強いファンダメンタルズ（反発の可能性）

## 6. 実装への重要な提言

### 6.1 必須実装要素
1. **多重時間窓分析**
   - 最低3つの時間スケール（120日、240日、360日）
   - 各窓でのフィッティング結果を統合評価

2. **2段階信頼性評価**
   - Confidence指標: バブルの存在を検出
   - Trust指標: 検出の信頼性を評価

3. **クラスタリングによる予測統合**
   - 個別のフィットではなく、クラスターの統計量を使用
   - シナリオ確率を明示

### 6.2 アセットクラス別の調整
- **株式**: 中期窓（200-500日）を重視
- **コモディティ**: 短期窓（100-300日）で急激な変動を捕捉
- **債券**: 長期窓（500-1000日）で構造的変化を分析
- **仮想通貨**: 極短期窓（50-200日）でボラティリティに対応

### 6.3 法的リスク回避の工夫
1. **確率的表現の使用**
   - 「クラッシュする」ではなく「クラッシュ確率X%」
   - 複数シナリオの提示

2. **免責事項の明記**
   - 「研究・教育目的」の強調
   - 投資判断は利用者の責任

3. **不確実性の可視化**
   - 標準偏差（σtc）を常に表示
   - 予測窓（60%確率窓、90%確率窓）の提示

## 7. FCOサービスの特徴と差別化要素

### 7.1 強み
- **学術的裏付け**: ETH Zurichの研究成果
- **長期実績**: 2009年から継続的に運用
- **透明性**: 手法と結果を公開
- **多資産対応**: 450以上の体系的資産を分析

### 7.2 制約
- **月次更新**: リアルタイムではない
- **欧米中心**: アジア市場のカバレッジが限定的
- **仮想通貨**: 24/7市場への対応が不完全
- **APIなし**: プログラマティックアクセス不可

### 7.3 あなたのサービスの差別化機会
1. **アジア市場特化**: 日経225、TOPIX、韓国、中国市場
2. **仮想通貨24/7対応**: リアルタイム分析
3. **API提供**: 自動取引システムとの連携
4. **日本語対応**: 技術解説を含む充実したコンテンツ
5. **高頻度更新**: 日次または週次更新
