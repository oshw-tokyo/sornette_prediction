# FCO v2.0 ローカルデータストレージアーキテクチャ移行計画

## 📅 作成日: 2025-09-13

## 🎯 移行の目的

1. **API依存の削減**: 分析実行時のAPI呼び出しを完全に排除
2. **高速化**: ローカルデータから直接読み込みによる処理速度向上
3. **安定性向上**: API制限・ネットワーク障害の影響を受けない
4. **責任分離**: データ取得と分析ロジックの明確な分離

## 📊 データ容量検証結果

### 実測値
- **1銘柄あたり（2年分）**:
  - CSV形式: 約27KB
  - Parquet形式: 約17KB
- **81銘柄全体（2年分）**:
  - CSV形式: 約2.1MB
  - Parquet形式: 約1.3MB

**結論**: データ容量は非常に小さく、全銘柄の長期データをローカル保存しても問題なし

## 🔄 移行ステップ

### Phase 1: データ基盤構築（優先度: 高）
1. **市場データダウンローダー作成**
   - 全銘柄の過去2年分データを一括取得
   - Parquet形式で階層的に保存
   - メタデータ（取得日時、ソース等）を記録

2. **データ更新システム構築**
   - 日次で最新データのみ追加取得
   - 既存データとの重複チェック
   - データ整合性検証

### Phase 2: 分析システム改修（優先度: 高）
1. **FCO分析エンジン改修**
   - API呼び出しを完全に削除
   - ローカルParquetファイルからの読み込みに統一
   - データ期間の柔軟な指定対応

2. **日次スケジューラー改修**
   - データ更新とFCO分析を別プロセスに分離
   - データ更新 → 分析の順次実行
   - エラー時の部分再実行対応

### Phase 3: 既存システム統合（優先度: 中）
1. **LPPL分析の移行**
   - FCOと同様にローカルデータ参照に変更
   - 週次スケジューラーも同様に改修

2. **ダッシュボード改修**
   - ローカルデータからの直接読み込み
   - リアルタイムデータ取得オプションの追加

## 🔧 技術的考慮事項

### データ形式
- **Parquet採用理由**:
  - 列指向で時系列データに最適
  - 高圧縮率（CSVの約60%サイズ）
  - 高速な読み込み（特に部分読み込み）
  - メタデータ埋め込み可能

### 更新戦略
- **追記型更新**: 既存ファイルを上書きせず追記
- **日次スナップショット**: 各日のデータを個別保存
- **定期的な再構築**: 月次で連結ファイル再生成

### エラーハンドリング
- **部分失敗対応**: 一部銘柄の失敗が全体に影響しない
- **リトライ機構**: 失敗したデータのみ再取得
- **データ検証**: 取得後の完全性チェック
