# Sornetteモデル分析プラットフォーム 法的準拠サービス仕様書

## エグゼクティブサマリー

本文書は、金融商品取引法の投資助言業規制を完全に回避しつつ、ユーザーに価値を提供する**データ分析プラットフォーム**の実装仕様です。サービスは学術的な数理モデルの計算結果を提供し、ユーザー自身が追加分析を行うツールとして位置付けます。

---

## 1. サービスの基本設計思想

### 1.1 法的位置付け

**「学術研究ツール提供サービス」**として以下の3原則を厳守：

1. **データ提供原則**: 数値データと統計値のみを提供（解釈・判断を含まない）
2. **研究教育原則**: 全コンテンツの40%以上を教育・研究要素で構成
3. **ユーザー分析原則**: 最終的な判断に至るには必ずユーザー独自の分析が必要

### 1.2 サービス名称（変更必須）

❌ **使用禁止**: 「LPPLクラッシュ予測サービス」
✅ **新名称**: 「Sornette理論研究プラットフォーム」または「LPPL分析ラボ」

## 2. 違法性リスクの除去

### 2.1 現行仕様の問題点と改善案

| 現行仕様（違法リスク高） | 改善後（合法） | 理由 |
|------------------------|--------------|------|
| 「○月○日頃に暴落リスク高」 | 「tc値: 2025.95（数理モデル出力）」 | 投資判断ではなく数値データ |
| 赤・黄・緑の信号機表示 | DS-LPPLS Confidence: 0.76 | 売買シグナルの誤解を回避 |
| 予測クラッシュ日カウントダウン | tc収束分布グラフ | 統計的分布の可視化 |
| 危険度一覧表示 | 数理モデル指標一覧 | 「危険」という判断を含まない |
| アラート機能 | データ更新通知 | 投資タイミング示唆を回避 |

### 2.2 提供データの制限

```python
# 合法的なデータ提供例
{
    "symbol": "N225",
    "analysis_date": "2025-09-02",
    "lppl_parameters": {
        "tc": 2025.95,  # 数値のみ（「クラッシュ日」と表記しない）
        "m": 0.35,
        "omega": 7.2,
        "damping": 1.8
    },
    "ds_lppls_confidence": 0.76,  # パーセント表記を避ける
    "data_points": 126,
    "r_squared": 0.89
}

# 絶対に含めてはいけない要素
# ❌ "crash_probability": 85%
# ❌ "recommendation": "売り"
# ❌ "risk_level": "high"
# ❌ "action_required": true
```

## 7. 週次から日次への移行計画

### 7.1 現状と目標

**現状**: 週次（毎週土曜日）の定期分析
**目標**: 日次分析への段階的移行

### 7.2 移行の理由

- より細かい市場変動の捕捉
- ユーザーへのタイムリーな情報提供
- 競合サービスとの差別化

### 7.3 段階的移行計画

```
Phase 1（現在）: 週次分析
    ↓ (3ヶ月)
Phase 2: 週3回分析（月・水・金）
    ↓ (3ヶ月)
Phase 3: 平日毎日分析
    ↓ (6ヶ月)
Phase 4: 日次分析（土日含む）
```

### 7.4 技術的考慮事項

```python
# 現在の実装（週次）
SCHEDULE_CONFIG = {
    'frequency': 'weekly',
    'day': 'saturday',
    'time': '09:00',
    'window_size': 365  # 1年分のデータ
}

# 将来の実装（日次）- 慎重な移行が必要
FUTURE_CONFIG = {
    'frequency': 'daily',
    'time': '09:00',
    'window_size': 365,
    # 以下の影響範囲に注意
    'database_impact': 'データ量が7倍に増加',
    'api_impact': 'API制限の再検討必要',
    'performance_impact': '計算負荷の最適化必須',
    'cost_impact': 'インフラコスト増加'
}
```

### 7.5 移行時の注意点

**影響を受けるコンポーネント**:
1. **データベース設計**: インデックス最適化、パーティショニング検討
2. **API制限管理**: レート制限の再設計、キャッシング戦略
3. **計算リソース**: 並列処理の実装、バッチ処理の最適化
4. **ダッシュボード**: 大量データの効率的な表示方法
5. **コスト管理**: クラウドリソースのスケーリング戦略

**リスク軽減策**:
- 段階的なロールアウト（特定銘柄から開始）
- A/Bテスト（一部ユーザーで先行実施）
- ロールバック計画の準備
- パフォーマンスモニタリングの強化
